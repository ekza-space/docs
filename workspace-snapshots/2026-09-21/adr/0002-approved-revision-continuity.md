# ADR 0002. Независимый выбор версии каждой игрой

- Дата: 2026-09-21.
- Статус: реализовано локально после согласия основателя на рекомендации ревью.
- Заменяет правило «новая публикация отзывает все одобрения» из ADR 0001.
- Проверка и выпуск: `../ekza-registry/docs/stabilization-release.md`.

## Проблема

Глобальный `current_revision_id` годится для витрины, но не для независимых игр.
Автор публикует улучшение, а игра ещё не успела его принять: игрок теряет ранее
работавший аватар. Требования повторной проверки точных байтов не требуют такого
разрыва доступности.

## Решение

`studio.project_releases` хранит выбранную rendition для пары «аватар, игра,
платформа, профиль». Приёмка опубликованной версии переключает только эту игру.
Приёмка до публикации вступает в силу после решения куратора. Без новой приёмки
игра остаётся на своём прежнем файле. Явное одобрение повторно поданной старой
версии может служить управляемым откатом игры; автоматического отката нет.

Указатель не удаляется при отзыве заявки. Он остаётся барьером: прежняя одобренная
версия не должна самопроизвольно появляться вместо отозванной. Представление
`active_project_releases` проверяет публикацию, статус заявки, готовность файла,
принятие профиля игрой и отсутствие удаления аккаунта.

Глобальное снятие аватара с публикации (`current_revision_id = NULL`) блокирует все
выбранные версии. Удаление аккаунта сохраняет существующие блокировки и каскады.
Повторная публикация — явное действие куратора, возвращающее разрешённые версии.

## Контракты

- Форма `/v2/avatars` сохраняется. Одна запись описывает конкретную ревизию;
  `origin.revisionId` и hash идентифицируют точные файлы.
- Без фильтра игры один avatar ID может встречаться в нескольких записях:
  игры могли выбрать разные ревизии. Нельзя объединять `projectSupport` разных
  записей по одному ID и тем самым переносить одобрения между файлами.
- Для конкретной игры и профиля выдаётся выбранная версия; библиотека аккаунта
  использует то же правило. Slug остаётся хэшем identity + rendition hash.
- Файл доступен по хэшу, пока хотя бы одна игра активно принимает эту rendition.
  Для превью добавлен `/v1/studio/assets/{sha}/rendition-thumbnail`.
- Старые `/v1/avatars`, `/library/avatars` и Mirror не мигрируются этим решением.
  Mirror пока использует текущую опубликованную iOS-версию.

## Связанные решения стабилизации

Неполный каталог — ошибка 503, а не успешный пустой список. SDK оставляет
сохранённый каталог и использует совместимость с v1 только при 404 v2; прежний
частичный ответ 200 с `X-Studio-Status: unavailable` тоже отклоняется.

Registry прекращает отдавать отозванный файл сразу. Это не удаляет скачанные
копии и не меняет модель в уже идущем матче. В Omoba повторная проверка каталога
происходит при следующем входе после истечения пяти минут; при сбое сохраняется
последнее успешное решение. Более строгий отзыв в ходе матча — отдельная функция.

Обработка Studio (ревизия USDZ и rendition) выполняется в изолированных заданиях
Docker. Образ установлен заранее и закреплён digest; сеть отключена, корень и
явно разрешённые входные файлы доступны только для чтения, запись — в папку
попытки. Отсутствие runtime/configuration завершает обработку ошибкой, без обхода.
